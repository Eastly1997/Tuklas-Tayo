IMPLEMENTATION
Four shared, stateless production component families live only in core:designsystem:
- TuklasTayoButton: filled, filled tonal, outlined, elevated, text; enabled/disabled, RowScope slot.
- TuklasTayoCard: filled/elevated/outlined; static or clickable; enabled applies to clickable cards.
- TuklasTayoChip: assist, suggestion, filter and input. Only filter/input accept selection state.
- TuklasTayoTextField: filled/outlined, hoisted editing, labels/placeholders, error/supporting text,
  disabled/read-only, icon slots and keyboard options/actions.
Material 3 owns their themed colors, typography, shape, semantics and standard interactions.
Approved theme/token files were retained. No restaurant-specific UI was implemented.

Existing Discover Explore/Retry buttons and the shared placeholder Back button now consume
TuklasTayoButton, with unchanged labels and callbacks. The theme showcase and new previews
consume the same production functions. No component styling was copied into feature/gallery code.

DEBUG GALLERY
Separate launcher label: TuklasTayo UI Kit.
Activity: com.tuklastayo.app.designgallery.DesignGalleryActivity.
All Gallery code/resources and its manifest overlay are under app/src/debug.
Sections: 36 live colors/hex values; 15 typography roles; shapes/spacing; button/card/chip/field
variants and states; clearly labeled direct Material references (checkbox/radio/switch/progress).
Local saveable Compose state handles Light/Dark/System, selection, editing and reference controls.
Buttons/cards show snackbars; fields have real user-triggered focus examples. Gallery window icon
appearance follows the chosen mode. No ViewModels, navigation, domain/data or Firebase/Koin imports
are used by Gallery UI.

Gallery declares :designgallery as a separate process. DebugTuklasTayoApplication returns before
app graph startup for that process; normal debug starts the same initializeAppGraph function as
release. This prevents Gallery startup from requiring the product graph. Runtime process/startup
behavior still needs the manual launch check; it was not exercised on a device.

MANUAL ACTIONS
1. Resolve the missing dependencies yourself with your authorized Gradle setup (JDK 21), then run:
   .\gradlew.bat :core:designsystem:compileDebugKotlin :app:assembleDebug :app:assembleRelease test
2. Install/run debug yourself and open TuklasTayo UI Kit in the app drawer, or select the Gallery
   Activity as the specified launch Activity in your own Android Studio run configuration.
3. Toggle Light/Dark/System, scroll all sections, click enabled/disabled demonstrations, toggle
   chips/reference controls, type in fields, trigger both focus examples and check snackbars.
   Check enlarged font settings, TalkBack, touch targets and system-bar icon contrast.
4. Inspect the Gallery and component Light/Dark previews manually.
5. Open the original TuklasTayo launcher and verify its existing navigation/actions.
6. On your own prepared/authorized device, run:
   .\gradlew.bat :core:designsystem:connectedDebugAndroidTest :app:connectedDebugAndroidTest
