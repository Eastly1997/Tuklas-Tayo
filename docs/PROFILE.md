# Separate Profile and Login ownership

The four modules are unchanged. Discover owns feature.discover.profile.ProfileScreen, ProfileUiState, ProfileAccount, avatar rendering, resources, previews and formatting tests. Profile has no app/Firebase/Credential Manager imports, auth observer, tokens or ViewModel. Its public rendering API is ProfileScreen(state, onSignInClick, onSignOutClick, modifier). ProfileUiState is immutable UI data: loading, optional account display fields, signing-out and error state.

App owns auth/login/LoginScreen and LoginRoute, the existing Activity-scoped LoginViewModel/LoginUiState, all auth domain/data/use cases, DI initialization and root navigation. app/profile/ProfileStateMapper.kt converts the existing auth state into Discover's UI model. This projection is not another session store and includes no UID or SDK objects. Sign-out is an app callback to the existing use case; Profile remains selected and changes to guest content in place.

Guest Profile is compact: neutral account avatar, Browsing as Guest, supporting copy and a primary Sign In callback. There is no Google button, brand welcome logo or credential request in Profile. The optional business information remains informational. Signed-in grouped account details/photo/fallback/read-only information and Sign Out retain their prior design and shared TuklasSectionContainer implementation.

App root graph contains the main experience and Login. Profile's Sign In callback navigates to root Login with launchSingleTop. The main NavBackStackEntry retains Discover's internal tab/scroll state. Login's own Scaffold supplies Back, neutral themed background, brand logo, welcome copy, the existing official Google button, loading/errors and no customer bottom navigation or Continue as Guest action. Back pops Login. Successful observed authentication, once resolved and not busy, is consumed once before popping Login, revealing the authenticated Profile. Cancellation/failure stays on Login with the existing safe feedback. No auth code is invoked merely by entering Profile/Login.

The old composable Profile slot and app-owned ProfileScreen/ProfileRoute are removed. Credential Manager configuration, parsing, Firebase exchange/repository, LoginViewModel state transitions and native splash are unchanged. Manage remains absent from runtime navigation pending trusted backend-managed authorization and backend access enforcement; authentication alone never grants access.

Tests: existing auth tests stay in app. New projection/return-decision tests cover the boundary. Profile rendering/formatting tests and offline previews move with the screen into Discover. Instrumented navigation source covers separate Login, absent customer tabs, recreation and Back returning to selected Profile. Device execution is manual: guest Profile -> Sign In -> Google -> authenticated Profile, cancellation/error retry, Back, sign-out, tab/scroll restoration, avatars, narrow/large-font/light/dark layouts, guest Discover startup and denied Manage access. No live-device result is implied by compilation.
